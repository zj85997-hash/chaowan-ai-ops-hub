# 潮玩电商 AI 运营中台 · 演示站

> 潮玩电商的运营每天要干 16 件事，这里把其中 8 件交给了 AI。
> AIY 黑客松扣子赛道成人组第一名作品的纯前端复刻：8 个 Agent 的判断都在浏览器里跑，数据全部虚构，断网也能用。

**在线演示**：https://zj85997-hash.github.io/chaowan-ai-ops-hub/

## 这是什么

目标用户是中小型潮玩电商平台的运营主管和客服主管。每天晚上 9 点到凌晨 1 点，是流水的最高峰，也是客诉的最高峰。这时候有三件事最难办：

- 大额投诉赔多少，全靠主管拍脑袋，平均要 2 小时才能给出答复。
- 社群要 8–12 个人轮班盯，还是会漏掉负面消息。
- 开一期新活动，选品、组箱、定价要 7–11 小时，算错一次整箱亏。

原版跑在扣子平台上，由 8 个 Bot、8 条 Workflow、4 个知识库和 Python 代码节点组成。这是团队作品，我负责统筹和路演主讲。

这个仓库是赛后重写的纯前端版本：

- 不依赖扣子，不需要账号，打开网页就能用；
- 用测试保证结果和原版文档里的算例一致。

## 8 个 Agent

| # | Agent | 替代的人力 | 做什么 |
|---|---|---|---|
| ① | 智能补偿决策 | 客服主管 1–2 人 | 按 user_id 精确查库，按补偿 SOP 分层算金额，附合规话术 |
| ② | 社群风控监控 | 社群运营 8–12 人 | 68 个敏感词分四级，做情感分析、跨群串联检测，给出响应时限 |
| ③ | 运营数据问答 | 数据分析 1–2 人 | 用自然语言问数，自动算环比，发现异常波动 |
| ④ | 智能选品推荐 | 选品 2–3 人 | 按二手热度、吸引力、售罄率、毛利四项打分，排除掉价风险款 |
| ⑤ | 智能组箱策略 | 组箱定价 3–4 人 | 分配六个赏级，验算成本上限和 40% 毛利线 |
| ⑥ | 智能积分兑换 | 兑换测算 1–2 人 | 算兑换目标商品的最优路径，以及还差多少积分 |
| ⑦ | 用户画像分析 | 用户运营 2 人 | 给用户打标签，算价值分和风险分，给出分层策略 |
| ⑧ | 智能客服问答 | 客服 7–8 人 | 意图识别、FAQ 检索、置信度计算，该转人工时带着结论转 |

## 设计原则

- **规矩交给知识库记，算数交给代码算。**
  - 补偿规则、敏感词、FAQ 写在 `assets/js/data.js`，改一句就生效。
  - 按 user_id 查消费记录、组箱成本验算、环比计算写在 `assets/js/engine.js`，结果 100% 准确，不会查错人、赔错钱。
- **统一输出契约。** 8 个 Agent 都输出同一种结构：`thinking`、`output.summary / metrics / detail / suggestion`、`meta.confidence / kb_hits`。前端只需要一个渲染器。
- **判断过程可见。** `thinking` 逐条显示，运营看得到 AI 依据什么下的结论。
- **AI 只出建议，人拍板。** 涉及钱的方案由人点「采纳」才生效，也可以手动改金额。

## 安全与合规边界

- 置信度低于 0.8 一律转人工，不编答案。
- 判定只看后台客观数据，不看用户投诉写得好不好，避免对表达能力弱的用户不公平。
- 涉及未成年人消费，最高优先级转人工，AI 不给金额。
- 补偿优先线上补货：实际发货并留存物流记录。
- 回收、转卖、收益类问题不作答，平台不参与、不担保任何私下交易。

## 本地运行

不需要安装任何东西，直接用浏览器打开 `index.html` 就行。也可以起一个本地服务：

```bash
python3 -m http.server 8000
```

测试用 Node 自带的测试框架，原版文档里的三个算例必须一字不差：

- VIP 大额亏损补偿 ¥32,800
- 高频投诉劝退结算 ¥480
- 80 份组箱成本 ¥2,831，毛利 40.02%

```bash
node --test tests/engine.test.mjs
```

页面的导航和页脚由 `build.py` 统一生成。改了 `build.py` 以后，运行：

```bash
python3 build.py
```
