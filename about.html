这是什么项目

AIY 黑客松扣子赛道成人组第一名的作品，原版跑在扣子平台上。这个演示站把同一套逻辑用纯前端重写了一遍，谁都能直接打开试。

01/Story

背景

目标用户是中小型潮玩电商平台的运营主管和客服主管。每天晚上 9 点到凌晨 1 点是流水最高峰，也是客诉最高峰：大额投诉赔多少全靠主管拍脑袋，社群要 8–12 个人轮班盯着还是会漏，开一期新活动的选品组箱定价要 7–11 小时，算错一次整箱亏。

原版在扣子平台上用 8 个 Bot、8 条 Workflow、4 个知识库和 Python 代码节点实现，外挂指挥中心看板、社群风控演示台和移动端对话页。团队作品，我负责统筹和路演主讲：把业务拆成智能体施工图纸、带队按时交付、上台路演。

这个演示站是赛后重写的纯前端版本：8 个 Agent 的判断逻辑都在浏览器里跑，不依赖扣子、不需要账号，用测试保证和原版文档里的算例结果一致。

02/Architecture

三层结构

展示层   指挥中心 · 社群风控演示台 · 组箱定价 · 知识库
            │  统一 JSON 输出契约
智能体层 ①补偿决策 ②社群风控 ③数据问答 ④智能选品
         ⑤智能组箱 ⑥积分兑换 ⑦用户画像 ⑧智能客服
            │  规则（语义） / 数据（精确查询）
数据层   补偿 SOP · 敏感词 68 + FAQ 31 · 运营与用户数据 · 商品库 50

一条最重要的设计：规矩交给知识库记，算数交给代码算。补偿规则、敏感词、FAQ 放知识库，改一句话立刻生效；按 user_id 查消费记录、组箱成本验算、同环比计算放代码，100% 准确，不会查错人、赔错钱。

04/Contract

统一输出契约

{
  "agent_id": "risk_monitor",
  "agent_name": "社群风控监控",
  "thinking": ["① 敏感词匹配……", "② 情感分析……", "③ 风险分级……"],
  "output": {
    "summary": "🔴一级高危，建议 15 分钟内响应",
    "metrics": [{"label": "风险等级", "value": "🔴一级高危"}],
    "detail": "### 风险概览 ……",
    "suggestion": "客服主管 15 分钟内在群内回应……"
  },
  "meta": {"latency_ms": 1800, "confidence": 0.95, "kb_hits": 5}
}
  • thinking：让判断过程对运营可见，不可见就不可信。
  • metrics：固定 2–4 个关键指标，一眼看结论。
  • confidence：低于 0.8 一律转人工，是安全阀不是装饰。
  • kb_hits：命中了几条知识库规则，证明结论有出处、不是编的。
05/Safety

安全与合规边界

AI 不做的四件事

  • 按 user_id 查数据不走语义检索，避免查错人、赔错钱。
  • 置信度低于 0.8 强制转人工，不编答案。
  • AI 只出建议，涉及钱的决定由人点「采纳」才生效。
  • 判定只看后台客观数据，不看用户投诉写得好不好。

业务侧

  • 出货概率在活动页公示；平台仅向 18 岁以上用户提供服务。
  • 涉及未成年人消费：最高优先级转人工，AI 不给金额。
  • 补偿优先线上补货，实际发货并留存物流记录。
  • 回收、转卖、收益类问题不作答：平台不参与、不担保任何私下交易。
06/How

这个演示站怎么做的

纯静态网站，零依赖：assets/js/data.js 是知识库和演示数据，assets/js/engine.js 是 8 个 Agent 的规则引擎，页面只负责展示。

用 Node 自带的测试框架写了 13 个测试，原版文档里的三个算例一字不差：VIP 大额亏损补偿 ¥32,800、高频投诉劝退结算 ¥480、80 份组箱成本 ¥2,831 / 毛利 40.02%。
